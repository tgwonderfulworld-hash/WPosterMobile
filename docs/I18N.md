# Localization (i18n)

Localization uses **the same architecture as WPoster Web**. Web uses `next-intl`;
its framework-agnostic core is **`use-intl`**, which runs in React Native and
consumes the **same message files** with the **same keys, namespaces and ICU
syntax**. There is no separate mobile translation system.

## Languages

Mirrors Web (`src/i18n/routing.ts`): **English, Русский, Deutsch, Español, Français**
(default: English). Adding a language in Web = drop its JSON here and add the code
in `SUPPORTED_LOCALES` — no screen changes.

## Files

| Path | Role |
| --- | --- |
| `src/i18n/messages/{en,ru,de,es,fr}.json` | **Copied verbatim from Web** — the source of truth (auto-syncable) |
| `src/i18n/mobile/{en,ru,de,es,fr}.json` | Small `mobile.*` overlay for RN-only microcopy (field labels, offline, validation, network errors) — keeps the Web JSONs pristine |
| `src/i18n/nest.ts` | Byte-for-byte port of Web's `nestMessages` (dotted-flat → nested) |
| `src/i18n/loader.ts` | Locale resolution + message loading (lazy per active locale) |
| `src/i18n/provider.tsx` | `AppIntlProvider` wrapping `use-intl`'s `IntlProvider` |
| `src/i18n/index.ts` | Barrel (re-exports loader + provider + `use-intl` hooks) |

> The barrel and provider are split into `index.ts` / `loader.ts` to avoid an
> index ↔ provider require cycle.

## Usage

```tsx
import { useTranslations } from '@/i18n';

function Screen() {
  const t = useTranslations();
  return <Text>{t('auth.login.title')}</Text>;      // real Web key
}
```

- App screens use **real Web keys** (`workspace.dashboard.*`, `workspace.sidebar.*`,
  `auth.*`, `errors.*`).
- RN-only strings use the **`mobile.*`** overlay (`mobile.fields.email`,
  `mobile.offline.banner`, `mobile.validation.*`, `mobile.net.*`).
- **Never** write literal UI strings: `<Text>Dashboard</Text>` ❌ →
  `<Text>{t('workspace.sidebar.dashboard')}</Text>` ✅.

## Language detection & switching

1. **First launch:** persisted preference → device language (`expo-localization`) →
   English fallback (`resolveInitialLocale`).
2. **Switching:** `setAppLocale(locale)` updates `appStore.language` (Zustand + MMKV),
   which re-renders `AppIntlProvider` → **applies immediately, no restart**, and is
   **persisted**.
3. UI: **Settings → Language** (native language names from `LANGUAGE_LABELS`).

## Validation (automated)

An audit script verifies: all 5 overlays have identical key sets; every app
namespace exists in every language; every literal `t()` key resolves; every runtime
key (`mobile.net.*`, `mobile.authErrors.*`, `mobile.validation.*`, `mobile.notices.*`)
exists in all 5 languages — i.e. **no missing translations, no fallback keys, no
mixed languages**.
